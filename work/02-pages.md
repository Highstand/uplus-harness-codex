# 페이즈 2 — 페이지 분해

이 문서는 화면·주소·상태·이동의 구현 계획이다. 현재 페이지 파일은 제목만 있는 틀이며, 아래 동작과 상태는 아직 구현하거나 브라우저에서 검증하지 않았다. 게이트 판정과 진행 상태의 원본은 메인이 관리하는 `work/progress.json`이다.

## 입력과 적용 기준

- [1단계 요구사항](01-requirements.md): 목표, 필수 규칙 9개, 제외 범위.
- [화면 설계서](../docs/screens.md): 화면 주소·구성 요소·상태·이동.
- [흐름도](../reference/flow%20chart.png): 이미지 직접 확인. 목록 → 상세 → 구독 신청 → 완료와 상세의 뒤로, 신청 취소 경로가 있다.
- [PRD](../docs/PRD.md) 3절·4절: 5개 화면의 주 흐름, 뒤로·취소·완료 후 행동, 상세 기능.
- [AGENTS.md](../AGENTS.md): 인터뷰 확정 사항이 우선한다. 실제 저장·접수는 제외하고 메모리 시연만 한다.
- `next.config.ts`의 `/` → `/plans` redirect를 읽어 확인했다. 초기 `app/page.tsx`는 제거하며 루트용 여섯 번째 페이지를 만들지 않는다.

## 화면과 주소 대응 — 5개

| 화면 | screens 주소 | Next.js 주소 | 페이지 파일 |
|---|---|---|---|
| 요금제 목록 | `/plans` | `/plans` | `app/plans/page.tsx` |
| 요금제 상세 | `/plans/:planId` | `/plans/[planId]` | `app/plans/[planId]/page.tsx` |
| 변경 전 확인 | `/plans/:planId/confirm` | `/plans/[planId]/confirm` | `app/plans/[planId]/confirm/page.tsx` |
| 변경 신청 | `/plans/:planId/apply` | `/plans/[planId]/apply` | `app/plans/[planId]/apply/page.tsx` |
| 신청 완료 | `/subscriptions/complete` | `/subscriptions/complete` | `app/subscriptions/complete/page.tsx` |

`:planId`와 `[planId]`는 같은 동적 경로이며, 실습의 유효한 값은 p01~p04다. 바텀시트·토스트·로딩·빈 상태·오류 상태는 기존 화면 안에서 표현하고 별도 페이지를 추가하지 않는다.

## 1. 요금제 목록

목적: 유형·데이터 조건·매달 내는 돈을 비교한다(US1·US2).

| 상태 | 표시와 동작 계획 |
|---|---|
| 기본 | 필터 4개 중 `전체` 1개 선택, 카드 p01→p02→p03→p04. 카드마다 매달 내는 돈과 24개월 후 월 요금 2개만 표시. p03이 보이면 추천 1개, 숨겨지면 0개. 유형 라벨 누락 없음 |
| 로딩 | Plan Card Skeleton 4개, 필터 조작 불가 |
| 빈 | `이 유형의 요금제가 없어요.` |
| 오류 | `요금제를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.`와 다시 불러오기 |

구성 요소: Header, FilterChip, icon/check, Card/Plan, Tag, Button. 신규: Plan Card Skeleton, Empty State, Inline Error.

이동: 최초 `/` 진입은 `/plans`로 연결한다. 카드 전체 선택 → `/plans/{planId}`. 상세의 뒤로, 확인의 다른 요금제 보기, 완료의 처음으로·브라우저 뒤로에서 돌아온다. 상세에서 돌아올 때 선택 필터를 메모리로 유지한다. 목록 자체의 별도 뒤로·취소 액션은 문서에 없다. 완료에서 돌아온 경우 신청 화면을 복원하거나 다시 제출하지 않는다.

## 2. 요금제 상세

목적: 요금 구성과 데이터 소진 후 속도를 확인한다(US2·US3).

| 상태 | 표시와 동작 계획 |
|---|---|
| 기본 | 요금제 요약, 유형·추천 여부, 매달 내는 돈·24개월 후 금액. 요금 구성은 정가·24개월 할인·매달 내는 돈 3줄. 할인은 regular_price − promo_price. 유형별 데이터·속도 안내, 변경 버튼 활성 |
| 로딩 | Detail Skeleton, 변경 버튼 비활성 |
| 빈 | 유효하지 않은 planId 등 요금제 없음: `요금제를 찾을 수 없어요.`와 목록 이동 |
| 오류 | `요금제 정보를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.`와 다시 불러오기 |

구성 요소: Header, icon/arrowLeft, Card/Plan, Tag, Card/Price, List/Row, BottomCTA, Button. 신규: Detail Skeleton, Empty State, Inline Error.

이동: 목록에서 진입한다. 상단 뒤로 → 필터를 유지한 `/plans`. `이 요금제로 변경하기` → 같은 planId의 `/plans/{planId}/confirm`. 변경 전 확인의 뒤로와 변경 신청의 취소도 이 상세로 돌아온다. 상세 자체의 취소 액션은 없다.

## 3. 변경 전 확인

목적: 이번 달 요금·위약금·유심 안내를 읽는다(US4).

| 상태 | 표시와 동작 계획 |
|---|---|
| 기본 | 선택 요금제 요약과 안내 3개를 모두 펼침. 접기 동작 없음. 이번 달 요금·위약금 안내 영역에 원 단위 숫자 금액 없음. 요금제 요약의 월 금액은 별도 |
| 로딩 | Confirm Skeleton, 하단 버튼 비활성 |
| 빈 | `선택한 요금제 정보가 없어요.`와 목록 이동 |
| 오류 | `변경 전 안내를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.`와 다시 불러오기 |

구성 요소: Header, icon/arrowLeft, Card/Plan, List/Row, BottomCTA, Button. 신규: Confirm Skeleton, Empty State, Inline Error.

이동: 상세에서 진입. 뒤로 → 같은 planId의 상세. `신청하기` → `/plans/{planId}/apply`. `다른 요금제 보기` → `/plans`. 별도 취소 버튼은 없다.

## 4. 변경 신청

목적: 이름·휴대폰 번호·동의를 검증하고 저장 없는 완료 시연으로 연결한다(US4). screens의 실제 저장 지시는 인터뷰 확정 사항으로 대체한다.

| 상태 | 표시와 동작 계획 |
|---|---|
| 기본 | 요금제 요약, 빈 이름·번호 Input 2개, 미선택 Checkbox 1개. 이름 1~20자 AND 010으로 시작하는 숫자 11자리 AND 동의일 때만 제출 가능 |
| 로딩 | Application Skeleton은 요금제 준비 상태에 사용. 제출 시 버튼 로딩·비활성으로 중복 실행 차단. 실제 저장 요청 없이 메모리에서 시연 1건 구성 |
| 빈 | 이름 또는 번호 미입력·동의 미선택이면 제출 불가. 이름·번호 포커스 이탈 시 PRD 오류 문구를 해당 필드에 표시 |
| 오류 | 이름 21번째 글자부터 입력을 막고 20자 제한 안내. 번호 형식 오류 안내. 실제 서버·네트워크 저장 실패는 이번 범위 밖이며 향후 연결 시 입력 유지·재시도 요구사항으로 남김 |

구성 요소: Header, Button(취소·보기·제출), Card/Plan, Input 2개, OptionItem, Checkbox 1개, BottomCTA. 신규: Privacy Bottom Sheet, Application Skeleton, Inline Error. 저장 실패용 Inline Error는 향후 연결 계획이며 실제 실패가 발생했다고 표시하지 않는다.

바텀시트: 이름·휴대폰 번호를 시연에 사용하는 점과 확정 문구 `실습 화면이며 입력한 개인정보는 저장하지 않습니다.`를 표시한다. 보관 기간은 실제 저장 연결 때 확정하며 임의 기간을 만들지 않는다. 닫아도 체크 상태는 유지한다. 별도 입력이나 페이지는 추가하지 않는다.

이동: 변경 전 확인에서 같은 planId로 진입한다. 유효한 입력의 시연 완료 → `/subscriptions/complete`. 상단 `취소` → 이름·번호·동의와 미완성 시연 데이터를 메모리에서 지운 뒤 같은 planId의 상세. 브라우저 뒤로의 별도 정책과 유효하지 않은 planId로 직접 진입했을 때의 안내는 원본에 없으므로 아래 미정 목록에 둔다.

## 5. 신청 완료

목적: 방금 만든 시연 1건을 확인한다(US5). 실제 통신사 접수가 아님을 명확히 표시한다.

| 상태 | 표시와 동작 계획 |
|---|---|
| 기본 | 시연 번호 SUB-숫자 6자리 1개, 요금제·월 금액·이름·010-****-1234 형식 번호·시연 일시. 제목과 상태는 시연 완료임을 명시. 복사 성공 시 토스트 2초 |
| 로딩 | Completion Skeleton, 복사·처음으로 버튼 비활성. 원격 저장 결과를 기다리는 것으로 표시하지 않음 |
| 빈 | 직접 진입·새로고침 등 메모리 데이터 없음: screens의 `확인할 신청 정보가 없어요.`와 처음으로 버튼만 표시. 서버·브라우저 저장소에서 복원하지 않음 |
| 오류 | 메모리 결과 표시 실패 안내와 처음으로 이동. 실제 접수 성공을 주장하거나 재저장하지 않음. 시연용 최종 오류 문구는 미정 |

구성 요소: icon/doneMark, Header, List/Row, Button(복사·처음으로), Card/Plan, Tag, BottomCTA. 신규: Caution Notice, Toast, Completion Skeleton, Empty State, Inline Error. screens에 열거된 `완료 정보 다시 확인` 버튼의 노출 조건은 상태 설명과 일치하지 않아 미정으로 보고한다.

이동: 변경 신청 시연 완료 직후 진입. `처음으로`와 이 화면의 브라우저 뒤로 모두 `/plans`. 신청 입력 화면으로 복귀하거나 시연을 중복 제출하지 않아야 한다. 완료 후 목록으로 나가면 신청 내용을 재조회하는 경로를 제공하지 않는다. 취소 액션은 없다.

## 메모리 연결 계획 — 구현은 페이즈 4

- 요금제는 PRD의 가상 데이터 4개를 읽는다. 필터만 현재 실행의 메모리에 유지한다.
- 신청 입력(name, phone, privacy_agreed)과 선택 plan_id는 메모리로만 다룬다. 번호 표시의 하이픈과 검증용 숫자를 구분한다.
- 시연 완료 데이터는 application_no, plan_id, name, phone, created_at 등 완료에 필요한 1건으로 구성한다. 번호는 시연용이며 영구 중복 방지를 보장하지 않는다.
- 신청→완료의 클라이언트 이동 동안 메모리 데이터를 전달하고, 새로고침으로 메모리가 없으면 빈 상태를 사용한다. URL·쿼리에도 개인정보를 넣지 않는다.
- 취소 시 입력을 제거한다. 완료에서 이탈한 뒤 이전 결과를 다시 조회하거나 브라우저 뒤로 제출을 재실행하지 않도록 이동과 메모리 수명을 함께 구현·검증한다.
- 데이터 구조와 시연 생성 함수의 연결 자리를 분리해 이후 Supabase로 연결할 수 있게 설계한다. 이번에는 실제 저장 함수·API·SDK 연결·서버 전송·DB·localStorage·sessionStorage를 사용하지 않는다.
- 로딩·조회 실패 상태는 screens의 상태 설계로 유지한다. 고정 데이터에 실제 원격 조회가 있다고 가장하거나 불필요한 지연·오류를 만들지 않는다. 각 상태의 실습 재현 방법은 미정이다.

## 출처 간 차이와 미정 사항

| 항목 | 출처와 차이 | 적용 또는 후속 확인 |
|---|---|---|
| 흐름도 화면 수·이름 | flow chart.png에는 변경 전 확인이 없고 `구독 신청`으로 표기. PRD 3절·screens에는 변경 전 확인을 포함한 5개 | 확정된 인터뷰와 screens를 따라 5개, `변경 신청` 사용. 원본 이미지는 수정하지 않음 |
| 저장·접수·보관 | screens 신청/완료, PRD 4-4·4-5는 저장 성공·접수 완료·보관 기간을 요구 | AGENTS의 메모리 시연과 비저장 안내가 우선. 완료 제목·상태·오류 문구는 실제 접수로 오인시키지 않는 최종 문구 확인 필요 |
| 신청의 이름 길이 | screens는 초과 오류, PRD 4-4는 21번째부터 입력 차단 | PRD의 차단과 오류 안내를 함께 적용. 20자 초과 값을 허용하지 않음 |
| 신청의 유효하지 않은 planId | screens 상세·확인은 빈 상태가 있으나 신청은 입력 빈 상태만 설명 | 신청 요금제 없음의 안내 문구·복귀 목적지 미정. 유효 요금제 없이 시연 진행 불가 |
| 브라우저 뒤로 | 완료의 뒤로 목적지는 명시. 신청의 취소는 상세지만 신청의 브라우저 뒤로·입력 처리와 다른 직접 진입 상황은 미정 | 완료는 목록 이동 필수. 나머지 미정 정책을 구현 전에 확인하고 임의로 취소와 동일시하지 않음 |
| 목록 필터 유지 범위 | 상세→목록은 유지 확정. 확인의 다른 요금제 보기·완료의 처음으로·새로고침 후 초기화 세부는 미정 | 상세 복귀 유지는 구현. 나머지 필터 정책은 확인 필요 |
| 완료 정보 재확인 버튼 | screens 구성 요소에는 있으나 빈 상태는 처음으로만, 오류 상태는 재저장 없음이라고 명시 | 재조회 기능은 제외. 이 버튼의 필요성과 노출 조건은 확인 전 추가하지 않음 |
| 복사 실패 | PRD·screens는 복사 성공 토스트만 정의 | 실패 안내 문구 미정. 실패를 성공으로 표시하지 않음 |
| 시연의 로딩·오류·빈 필터 재현 | screens는 상태를 명시하지만 고정 데이터 4개는 모든 필터에 결과가 있고 서버 요청도 제외됨 | 자동 실패 유발·지연·개발용 UI는 합의되지 않음. 상태 검증 방법을 후속 구현·검증 때 확인 |
